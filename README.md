# ИИ-агент для учебных Telegram-чатов

Локальный прототип для кейс-чемпионата. Агент отслеживает новые и изменённые сообщения в выбранных учебных чатах, определяет задания и переносы сроков, ищет похожие задания через RAG, пересылает важные сообщения в топики по предметам и поддерживает отсортированный список дедлайнов.

## Что уже реализовано

- Telegram long polling для нескольких исходных чатов и обработка `message` / `edited_message`.
- Локальная LLM через Ollama для решения `ignore`, `create`, `update`, `cancel`, `review`.
- Эмбеддинги через Ollama, поиск похожих заданий в SQLite; при установленном `sqlite-vec` используется его векторный индекс.
- Отдельная индексация корпуса из 10–100 учебных текстов. В комплекте 12 синтетических примеров для демонстрации.
- Собственный MCP-сервер и клиент по stdio: поиск, чтение и запись БД, пересылка в топики, публикация списка дедлайнов.
- Защита от повторной обработки одинакового сообщения, очередь сообщений для ручной проверки.
- Офлайн-демо без Telegram и LLM.

## Быстрый показ без учётных данных

Из корня проекта:

```powershell
python demo.py
python -m unittest discover -s tests -v
```

Демо использует сценарные ответы вместо настоящей модели и Telegram. Оно показывает обработку нового задания, перенос срока и игнорирование обычного сообщения. Это проверка логики, а не свидетельство успешной интеграции с реальным чатом.

## Запуск с Telegram и локальной моделью

Нужны Python 3.11+, Ollama и бот Telegram. Для ноутбука с 8 ГБ ОЗУ выбран `qwen3:4b-instruct`; при достаточной памяти можно заменить его на модель крупнее. Установите модели:

```powershell
ollama pull qwen3:4b-instruct
ollama pull nomic-embed-text
```

Создайте виртуальное окружение и установите векторное расширение:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если `sqlite-vec` недоступен, агент работает со встроенным поиском по векторам в SQLite. Для презентации варианта А рекомендуется установить расширение, чтобы показать именно векторную БД.

Создайте бота через `@BotFather`. Добавьте его в исходные группы как администратора либо отключите режим приватности. Добавьте бота в целевую супергруппу с включёнными топиками и правом писать сообщения. Создайте топики для предметов и отдельный топик «Дедлайны».

Скопируйте `.env.example` в `.env` и заполните токен, ID чатов и топиков. ID можно посмотреть, отправив тестовое сообщение после добавления бота и запустив:

```powershell
python -m study_agent.inspect_telegram
```

Если стандартная тема `General` переименована в предмет, укажите для этого предмета `0` в `SUBJECT_TOPICS`. Бот отправит сообщение в основную тему группы без `message_thread_id`. Для отдельных тем укажите их числовые ID.

Затем:

```powershell
python -m study_agent.cli check
python -m study_agent.index_corpus data/sample_messages.jsonl
python -m study_agent.cli run
```

Перед реальной защитой замените синтетический корпус на обезличенные сообщения своей предметной области. Формат: одна JSON-строка на текст с полями `subject` и `text`; объём от 10 до 100 строк.

Просмотр состояния:

```powershell
python -m study_agent.cli deadlines
python -m study_agent.cli review
```

Не запускайте одновременно `inspect_telegram` и `cli run`: оба читают одну очередь обновлений Telegram.

## Как работает RAG и MCP

1. MCP-инструменты `search_documents` и `find_similar_tasks` возвращают похожие тексты корпуса и до пяти активных заданий из векторного индекса.
2. Оркестратор передаёт сообщение и найденные записи LLM. Модель выбирает действие и, для изменений, ID конкретного задания.
3. Оркестратор проверяет предмет, формат срока и ID задания. После проверки вызывает MCP-инструменты `save_deadline`, `forward_to_topic`, `publish_deadlines`.
4. Исходное сообщение помечается обработанным. При повторе того же обновления действие не дублируется.

Схема проекта находится в `architecture.puml`.

## Границы прототипа

- Обрабатываются текст и подписи к вложениям. Распознавание изображений, голосовых сообщений и документов не реализовано.
- Бот видит сообщения только в чатах, где ему предоставлен доступ. Старую историю через Bot API этот проект не загружает. Telegram хранит непрочитанные обновления до 24 часов.
- Неоднозначные сообщения попадают в `review`; их следует проверить вручную. Изменения, присланные отдельным сообщением, могут требовать ручной проверки, если модель не находит убедительное совпадение.
- Дедлайн можно удалить из списка действием `cancel`, но автоматическая обработка удаления исходного сообщения не реализована.
- Реальный запуск с Telegram и Ollama требует токена, ID чатов и установленных моделей; офлайн-демо этого не заменяет.
